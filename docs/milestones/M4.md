## Golden set

The project owner had no time to photograph filled sheets (2026-11-12), so the set is synthetic: `apps/pwa/e2e/golden.spec.ts` prints the real templates, writes seeded handwriting-style entries (Latin and Ge'ez names, phones, codes), and tilts and shades the page like a phone photo. 10 pages: F × 4 (2 en, 2 am), C × 4 (2 sheets × en/am), O × 2. No real patients. To rebuild: `GOLDEN_OUT=../../packages/ai/golden pnpm --filter @yegna/pwa e2e golden`.

A correction is one field a human fixes on the review screen: a wrong or missing field on a matched entry, every field of a missed entry, or deleting an invented entry.

Groq, OpenRouter, Mistral OCR and Gemini were not measured: no keys on this machine yet.

**Reading:** the free on-account models find the sheet (ID 100%, so the right week and template are chosen) but cannot read a dense handwritten grid in one go. Per ADR 0009 §5 the target is relaxed: in the pilot the review screen is where entries are typed or fixed, and the import still saves time on the sheet, week and slot.

**Next steps to improve (not in M4):** (1) measure Groq/Gemini when keys exist (`GROQ_API_KEY=… pnpm eval:imports --reader groq`); (2) read the sheet in tiles (one day column or half-page per call), which small models handle much better, e.g. cropping with the Cloudflare Images binding; (3) add real pilot photos to the golden set.

## Lessons

- Print CSS must be scoped (`.paper-*`): a global `.sheet` rule broke the booking bottom sheets.
- `getPlatformProxy` cannot pass an `AbortSignal` to the AI binding (the deployed binding can); the eval drops it.
